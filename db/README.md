# ZevaPay — Database

The Prisma schema, migrations and seed script for ZevaPay. PostgreSQL 16 is
the only supported database.

## Configuration

| Variable       | Default                                                     |
| -------------- | ----------------------------------------------------------- |
| `DATABASE_URL` | **required** — `postgresql://zevapay:zevapay@localhost:5432/zevapay` |

Copy `.env.example` to `.env` and adjust. Never commit a real `.env`.

## Getting started

From the repository root:

```bash
npm run setup   # docker compose up -d, then migrate and seed
```

Or from this package:

```bash
npm install
cp .env.example .env
npm run migrate   # apply migrations and generate the client
npm run seed      # load the demo data
```

## Scripts

| Script               | What it does                                  |
| -------------------- | --------------------------------------------- |
| `npm run migrate`    | Apply migrations (creates one if needed)      |
| `npm run migrate:deploy` | Apply existing migrations only (production) |
| `npm run generate`   | Regenerate the Prisma client                  |
| `npm run studio`     | Browse the data in Prisma Studio              |
| `npm run seed`       | Load the demo data                            |

`npm run migrate:deploy` is the one to use in production. `migrate` is for
development, where it may create a migration for you.

## The generated client

The generator writes into `backend/src/generated/prisma`, not into this
package. Both the API and the seed script import the same instance, so there
is exactly one copy of the client in the repository. It is git-ignored and
regenerated by `npm run generate`.

```
generator client {
  provider = "prisma-client"
  output   = "../../backend/src/generated/prisma"
}
```

The path is relative to the schema file, so it resolves to
`backend/src/generated/prisma`.

## Layout

```
prisma/
  schema.prisma        # The models and enums
  migrations/          # Applied migrations, in order
seed/
  seed.ts              # The demo data
prisma.config.ts       # Prisma 7 configuration
```

## The model

| Model            | What it holds                                                |
| ---------------- | ------------------------------------------------------------ |
| `User`           | A person, their role, and which merchant they belong to      |
| `Merchant`       | A tenant: the business, its status and its plan               |
| `PaymentAccount` | A bKash / Nagad / Rocket / Upay account belonging to a merchant |
| `Device`         | An Android SMS Bridge device bound to a merchant              |
| `Transaction`    | A payment notification that was parsed and recorded           |
| `PairingCode`    | A short-lived code that binds a device to a merchant          |
| `Session`        | A refresh-token session, per device or browser                |
| `ApiKey`         | A merchant API key for server-to-server access                |
| `AuditLog`       | An append-only record of every meaningful action              |

Every tenant-scoped model carries a `merchantId`. The API enforces that
boundary on every read and write; the database stores the relation so it can
also be indexed and joined against.

## Migrations

Migrations are committed and applied in order. To change the schema:

1. Edit `prisma/schema.prisma`.
2. Run `npm run migrate` and let Prisma write the migration.
3. Commit both the schema change and the migration.

Never edit a migration that has already been applied.
